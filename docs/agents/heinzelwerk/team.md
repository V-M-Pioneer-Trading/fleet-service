# Team rules

How heinzelwerk agents work in this repo. Mode rules (single repo vs workspace) live in the `heinzelwerk:team-modes` skill. This file holds only what is specific to this repo.

- **Autonomy**: full. Agents merge and apply on their own; breakages are learnings. Secrets are never published (name the variable, never the value), and the gate never merges its own policy.
- **Backend paths**: whole repo (`src/`, `scripts/`)
- **Worktree setup**: `npm ci`
- **Checks** (copied from `.github/workflows/container.yml`, jobs `test`, `docker`, in order):
  - `npm run build`
  - `npm run openapi && test -z "$(git status --porcelain -- openapi.json)"`
  - `npm run lint`
  - `npm test`
  - `docker build .` (unverified locally: docker daemon not running; the `docker` job builds linux/arm64)
- **Checks verified on main**: 6346b94 2026-10-28
- **Coding standards**: `@v-m-pioneer-trading/eslint-config` base (`package.json:32`); conventions in `CLAUDE.md`
- **Risk areas** (validator reviews diffs touching these on Opus):
  - `src/auth.ts:27-28`: scope decided by HTTP method alone, so a new GET route is readable by any session
  - Money: `POST ships/{s}/refuel` (`src/controllers/ships.controller.ts:82-88`) spends credits; `POST contracts/{id}/deliver` (`src/controllers/contracts.controller.ts`) consumes cargo
  - `src/spacetraders/client.ts`: forwards the caller's Authorization verbatim to st-gateway; never log it
  - `.github/workflows/container.yml`: a merge to main deploys to production
- **Contracts** (see team-modes **Contract changes**):
  - API: `openapi.json` (generated by `npm run openapi`) · provider fleet-service; mirrored to `../meta/openapi/fleet-service.json`. Consumers: command-interface, automation-service
  - Consumed: st-gateway /proxy · provider st-gateway; agent-service `POST /contracts/{id}/deliveries` (best effort) · provider agent-service; auth-service introspection via clerk-client · provider auth-service
  - Scope literal `fleet:control`, pinned by `src/__tests__/scopeContract.test.ts` · provider auth-service
  - Vendored: `src/testSupport/gateway-errors.json`, copy of `../meta/fixtures/gateway-errors.json`, pinned only by its `$comment` (no sha) · provider meta
  - Shared packages: clerk-client 2.0.1 (`package.json:20`), eslint-config 1.1.0 (`package.json:32`)
  - Infra outputs: fleet-service stack, SSM document `fleet-service-bootstrap-<instance>` · provider infrastructure (`../V-M-Pioneer-Trading_infrastructure/fleet-service/`)
